3. MULTI-STREAM INGESTION & GPU ACCELERATION BACKEND (`app.py`)

A. Compute & Model Initialization:

* Check for PyTorch CUDA availability (`torch.cuda.is_available()`).
* If CUDA is detected, initialize YOLOv8 (`yolov8n.pt`) on `device=0` / FP16 precision. Otherwise, run on CPU with thread optimizations.
* Maintain separate, thread-safe frame buffers and inference queues for Camera 1 and Camera 2 to prevent thread contention or event loop starvation.

B. Stream 1 (Primary Camera - Laptop / USB):

* Ingest via OpenCV `cv2.VideoCapture(0)`.
* If physical device index 0 is unavailable, seamlessly fallback to an animated synthetic OpenCV canvas displaying mock shelf items and wandering centroids.

C. Stream 2 (Secondary Camera - Smartphone Streaming Client):

* Provide a dual-ingestion mechanism for the mobile camera:
1. Direct Mobile Web Client (`GET /mobile_cam`): A dedicated, mobile-friendly HTML5 page that accesses the phone's rear camera via `navigator.mediaDevices.getUserMedia` and transmits compressed JPEG frames to a backend WebSocket endpoint (`/ws/mobile_upload`) at 15–20 FPS.
2. IP Camera URL Fallback (`POST /api/config/camera2_url`): Accepts an RTSP/HTTP MJPEG URL (e.g., from IP Webcam apps) for network IP cameras.


* If the mobile connection drops or has not yet connected, render an elegant "Awaiting Secondary Camera Connection (Scan QR / Visit /mobile_cam)" placeholder frame rather than crashing or throwing unhandled exceptions.

D. Dynamic Role Swapping & Reconfigurable State Machine:

* Both cameras must support dynamic role assignment via UI/API (`POST /api/config/roles`):
* `cam1_role`: "SHELF" | "QUEUE"
* `cam2_role`: "QUEUE" | "SHELF"


* **Shelf Monitoring Logic:**
* Track retail objects: `bottle`, `cup`, `can`, `book`, `bowl`, `cell phone`.
* Calculate stock percentage: `(current_items / max_shelf_capacity) * 100`.
* Centroid-Shelf Interaction Matrix (CSIM) Occlusion Filter: If a `person` bounding box overlaps the Shelf Region of Interest (ROI), switch status to `CUSTOMER_BROWSING` and suppress out-of-stock alarms.
* Out-of-Stock Debounce: If item count is 0 AND no customer occlusion is active continuously for >= 2.0 seconds, transition state to `OUT_OF_STOCK_ALERT` ("Restock Required Immediately").


* **Queue Monitoring Logic:**
* Detect and count `person` class centroids within the defined Queue boundary.
* Compute estimated checkout wait time: `queue_count * 1.5` minutes.
* Congestion Trigger: If `queue_count >= 2`, transition state to `CONGESTION_ALERT` ("Long Line Detected — Dispatch Register 2 Cashier").
